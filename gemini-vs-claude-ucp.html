UCP REST — standard JSON/HTTP, interoperable with any AI model

HTTP to UCP endpoints — /ucp/products, /ucp/cart/items, /ucp/orders

Claude · MCP path

1
Buyer message arrives at storefront
Next.js storefront opens an SSE stream to the Claude shopping agent's MCP server endpoint.
POST /mcp (streamable HTTP)
2
Skill router classifies intent
The prompt + skills[] are sent to claude-sonnet-5. It selects the Browse skill, then Add to Cart skill — two model calls with focused system prompts.
messages.stream(model="claude-sonnet-5")
3
Claude calls search_products tool
Tool result flows back in-band over the same MCP stream. Claude calls the Python function directly — no HTTP request to a separate service.
StorefrontBackend.search_products()
4
MCP UI Resource: product grid
Server emits a ui SSE event containing a ui://storefront/product-grid resource. The storefront renders it instantly — no round-trip.
event: ui · type: product_grid
5
always_ask gate fires on add_to_cart
The write-tool permission gate pauses execution and emits a confirmation prompt SSE event. The buyer must approve before the cart is mutated.
permission: always_ask → buyer confirms
6
Claude calls place_order tool
After a second always_ask gate, the Python method calls Salesforce B2B Commerce REST directly — create cart → add items → activate Order SObject.
SF B2B Commerce API · /sobjects/Order
7
Order confirmation UI streamed
Server emits a ui://storefront/order-confirmation MCP UI Resource. Storefront renders the card live while Claude is still writing the confirmation text.
event: ui · type: order_confirmation
8
Haiku extracts memory
Post-turn, claude-haiku-4-5 reads the conversation and updates the buyer's preference store — e.g. "prefers ruggedized laptops, PO payments".
memory model: claude-haiku-4-5
✨

Gemini · UCP path

1
Buyer message arrives at storefront
React storefront sends a POST to the FastAPI bridge (gemini_web_server.py) running on Railway. Response is a single JSON object.
POST /api/chat → JSON response
2
GeminiUCPAgent fetches manifest (once)
On first startup the agent calls GET /.well-known/ucp, reads the capability manifest, and auto-builds FunctionDeclarations. No store-specific code needed.
GET /.well-known/ucp · RFC-8615
3
Gemini calls search_products function
Gemini returns a FunctionCall part. The Python agent executes an HTTP GET to the UCP REST endpoint and feeds the JSON result back as a FunctionResponse.
GET /ucp/products?q=laptop
4
Products returned in JSON response
No SSE events. When the final JSON arrives, the frontend reads data.products and renders product cards from that payload.
response.products[] · per-turn sync
5
System prompt governs confirmation
No protocol-level gate. The system prompt instructs: "always confirm items and total with the user before calling place_b2b_order." Gemini decides when to proceed.
system_instruction: confirm before order
6
Gemini calls place_b2b_order function
Agent POSTs to /ucp/orders, which runs the full 9-step Salesforce flow: create cart → add items → set PO number → create Order SObject → activate → close cart.
POST /ucp/orders → SF B2B Commerce API
7
Order confirmed in JSON response
When the full response arrives, the frontend reads data.tool_calls — finds place_b2b_order — clears cartItems state and hides action buttons.
data.tool_calls[].tool === "place_b2b_order"
8
No memory extraction
Conversation history is kept in _contents[] in memory for the session. On reset or redeploy, all context is lost — no cross-session preference store.
session: _contents[] · in-process only

The UCP manifest bridges both worlds

The GET /.well-known/ucp response is what Gemini reads at startup to auto-build its tools. Notice it also advertises the MCP transport — so a Claude agent can discover the richer path from the same manifest.

// GET /.well-known/ucp → served by ucp.py (FastAPI router) { "schema_version": "1.0", "business": { "name": "ACME Commerce" }, "capabilities": { "product_discovery": { "supported": true, "endpoints": { "search": "/ucp/products", ← Gemini calls this "detail": "/ucp/products/{product_id}" } }, "cart_management": { "supported": true, "endpoints": { "add_item": "/ucp/cart/items" } }, "checkout": { "supported": true, "endpoints": { "create_session": "/ucp/checkout-sessions" } } }, "transport": { "rest": { "base_url": "https://…railway.app", ← Gemini uses this "auth": "UCP-Agent" }, "mcp": { "protocol": "streamable-http", ← Claude uses this "description": "Richer Claude agent with memory, skills, and SSE UI" } }, "agent_hints": "Prefer MCP for complex journeys. Use REST for single-turn lookups." }

Where both paths converge

Regardless of protocol, both Claude and Gemini eventually call the same Python interface and the same Salesforce APIs. The shared layer is what makes the platform model-agnostic.

StorefrontBackend
12-method Python interface: search_products, get_cart, add_to_cart, place_order, get_order, and 7 more
Salesforce OAuth2
Client-credentials token at /services/oauth2/token. Same credentials, same scopes.
B2B Commerce REST
/commerce/webstores/{id}/carts · cart-items · products. API v62.0.
SObject CRUD
Order, OrderItem, WebCart, Quote — same 9-step activation flow for both paths.
Product Catalog
Same SOQL queries, same Product2 objects, same pricing and entitlement checks.
Railway Deployment
Single Railway service runs both the UCP REST endpoints (for Gemini) and the MCP server (for Claude).
When to choose each path
Both are production-ready. Choose based on what matters for your integration.

Choose Claude (MCP) when…

  • You need real-time streaming UI — tokens and product grids appear as Claude thinks
  • Buyer safety is critical — always_ask gates enforce confirmation at the protocol level
  • You want persistent memory — buyer preferences survive across sessions and redeploys
  • Complex multi-step journeys — 5 focused skills each with tuned system prompts
  • Rich tool set matters — enrichment, delivery promises, policy lookups, fulfillment options
  • You're already on Anthropic (direct API, Bedrock, Vertex, Azure AI Foundry)

Choose Gemini (UCP) when…

  • You want model-agnostic REST — any AI model can call your store without custom integration
  • Speed of integration matters — zero store-specific code; manifest auto-builds the tools
  • You're building for Google ecosystem — Gemini, Vertex AI, AI Studio
  • Simple commerce journeys — add to cart, place PO, save quote
  • Portability — UCP endpoints work with Gemini today, GPT-4o tomorrow
  • You want discoverable storefronts — publish /.well-known/ucp and any compliant agent connects
