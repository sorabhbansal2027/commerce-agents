MCP Server Code
# storefront_mcp_server.py — key patterns

# 1) Server binds loopback only (no auth = no off-loopback)
enforce_local_only_bind(host, server="storefront", unsafe_env_var="STOREFRONT_MCP_UNSAFE_ALLOW_NO_AUTH")

# 2) One ShoppingToolExecutor per MCP connection (provenance isolation)
executors = ConnectionExecutors(
    lambda: ShoppingToolExecutor(backend=backend, config=cfg, session=session, ...)
)

# 3) Tool registered via registry contract (same description as other paths)
register = registrar(server, contracts_by_name(build_tools(cfg)), HOSTED_DESCRIPTION_OVERRIDES)

# 4) Regular tool
@register("search_products")
async def search_products(query: str, ctx: Context, ...) -> str:
    return await executors.call(ctx, "search_products", {"query": query, ...})

# 5) MCP Apps (SEP-1865) — UI resource
@server.resource("ui://storefront/product-grid", mime_type="text/html")
def product_grid_ui() -> str:
    return _PRODUCT_GRID_HTML   # product_grid_ui.html

# 6) search_products_ui — attaches ui:// resource to result
@server.tool(name="search_products_ui", description="...for MCP Apps hosts...")
async def search_products_ui(query: str, ctx: Context, ...) -> mcp_types.CallToolResult:
    result_text = await executors.call(ctx, "search_products", ...)
    return mcp_types.CallToolResult(
        content=[mcp_types.TextContent(type="text", text=result_text)],
        meta={"ui": {"resourceUri": "ui://storefront/product-grid"}},  # MCP Apps SEP-1865
    )
SSE Event Flow — Messages API Path (Next.js / Salesforce LWC)
Server side — how events are produced
📡
AgentEvent types
Defined in commerce_common/streaming.py. Each is a typed dict with type + data fields.
AgentEvent.cart_update(cart) → {type:"cart_update", data:{cart:{...}}} AgentEvent.turn_complete(...) → {type:"turn_complete", data:{...}}
🔄
to_sse() formatter
Converts AgentEvent to SSE wire format. event: line carries the type; data: carries the JSON payload dict.
streaming.py:to_sse() → "event: cart_update\ndata: {...}\n\n"
🌊
Streaming pipeline
host.py:189 yield to_sse(event) inside stream_turn(). FastAPI's StreamingResponse flushes each chunk immediately.
host.py:171 stream_turn() → StreamingResponse(media_type="text/event-stream")
Client side — LWC event handler
📱
_readStream() loop
salesforceStorefront.js reads the SSE response body as a stream. Each \n\n-delimited frame is parsed into {type, data}.
salesforceStorefront.js:_startTurn() → _readStream() → _handleEvent()
🛒
cart_update handler
Sets this._cart = event.data.cart. Does NOT call _loadCart() — trusts the SSE payload. (Fix: removed post-turn _loadCart() that was overwriting correct cart with stale SOQL data.)
if (cart && cart.items !== undefined) this._cart = cart
💬
text_delta handler
Appends event.data.text to the current assistant message bubble. Triggers reactive re-render.
🎨
ui / ui_partial handler
Dispatches to generative component renderer. ui_partial streams the component JSON; ui commits it. Components: products, comparison, plan, guide, order_status, checkout.
💡
suggestions handler
Sets this._suggestions array → renders follow-up chips below the response.
✅
turn_complete handler
Sets this._isBusy = false. Calls _loadOrders() (not _loadCart() — cart was already updated via cart_update).
salesforceStorefront.js:792 finally block

Universal Commerce Protocol (UCP)
UCP Capability Manifest
🗺️
Discovery endpoint
External AI agents (Gemini, etc.) fetch GET /.well-known/ucp to discover what this storefront supports. Returns a JSON manifest with capabilities, endpoints, and transport hints.
demo_common/ucp.py · Cache-Control: public, max-age=300
📦
Capabilities advertised
product_discovery: full_text_search, category_filter, price_range_filter, availability_filter (max 50/page)
cart_management: requires session (POST /ucp/sessions)
checkout: pending confirmation sessions — no charge made
🚗
Transport hints
Manifest advertises both REST and MCP transports. Agents are nudged toward MCP for complex journeys (memory, policy search, fulfillment options, interactive UI).
agent_hints: "Prefer MCP for complex shopping journeys."
UCP REST Endpoints
🔍
GET /.well-known/ucp
Capability manifest. Sessionless, public. Mounted at domain root per RFC 8615.
📋
GET /ucp/products
Sessionless product search. Params: q, category, min_price, max_price, in_stock, limit (max 50).
GET /ucp/products?q=laptop&max_price=1300&in_stock=true
📦
GET /ucp/products/{id}
Single product detail. product_id may contain slashes.
💳
POST /ucp/checkout-sessions
Create a pending checkout session from line items. No charge. Returns session_id + subtotal + status: "pending".
Body: {line_items, buyer, payment_handler}
📊
GET /ucp/checkout-sessions/{id}
Status of a checkout session. Reference impl: not persisted. Production: integrate with OMS.
UCP vs MCP — when to use which
UCP — Universal Commerce Protocol
✓ Single-turn product lookups by external AI agents (Gemini, etc.)
✓ Sessionless — no auth required for product_discovery
✓ Standard REST — works with any HTTP client
✓ Checkout session creation without agent session
✗ No memory, personalization, or policy search
✗ No interactive UI blocks
✗ Cart writes require /ucp/sessions (stub only in reference)
MCP — Model Context Protocol
✓ Full shopping journey: search + cart + memory + policies
✓ Interactive UI via MCP Apps (SEP-1865) resources
✓ Provenance gates, quantity caps, cart locks enforced
✓ Session-aware: one executor per connection
✓ Managed Agents: Anthropic platform runs the loop
✗ Requires credential in vault + HTTPS tunnel
✗ Not sessionless — needs connection setup
