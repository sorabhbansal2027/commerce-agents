🐳 Docker Build (Dockerfile.gemini)

Two-stage: Node.js builds React → Python serves everything
🧱 Stage 1 — Builder (node:20-slim)
FROM python:3.11-slim AS builder
RUN install Node.js 20 via NodeSource
COPY examples/gemini-storefront/package*.json
RUN npm ci  ← layer-cached by package-lock hash
COPY examples/gemini-storefront/
RUN npm run build  → dist/ with hashed filenames
→
🐍 Stage 2 — Runtime (python:3.11-slim)
COPY requirements-gemini.txt
RUN pip install fastapi uvicorn httpx google-genai
COPY scripts/gemini_web_server.py
COPY examples/demo_common/gemini_ucp_agent.py
COPY --from=builder /build/storefront/dist
CMD python scripts/gemini_web_server.py
⚡

Why one container? FastAPI mounts dist/ as a static files route. Both the React app and the /api/* endpoints run on the same port (8090 → Railway's PORT), so no CORS configuration is needed in production and there's no separate web server (nginx) to maintain.

🔄 Request Flow — Place a Purchase Order

Full trace from user click to Salesforce order number
Browser → Railway → Gemini → Salesforce (10 steps)
1
User enters PO number and clicks "Place →"
CartSidebar.submitPO() → checkoutPO() → sendMessage(text)
2
Browser: POST /api/chat
{ "message": "Please place a purchase order for: [items]. PO: XXXXX" }
3
Railway resets per-turn state
agent.last_tool_calls = [] · agent.cart_additions = [] · agent.checkout_session = None
4
Railway → Google Gemini API: generate_content()
Sends full conversation history + tool declarations · Model: gemini-3.6-flash
5
Gemini returns function_call: place_b2b_order
{ "payment_handler": "purchase_order", "po_number": "XXXXX" }
6
Railway → Salesforce: OAuth token exchange
POST {SF_COMMUNITY_URL}/services/oauth2/token (Connected App credentials)
7
Railway → Salesforce: Create/get WebCart, add CartItems, set PO
B2B Commerce REST v62: /commerce/webstores/{id}/carts · /cartItems · PATCH cart
8
Railway → Salesforce: Create Order SObject + OrderItems
POST /services/data/v62.0/sobjects/Order · sobjects/OrderItem (batch)
9
Railway → Salesforce: Activate order, read OrderNumber
PATCH Order Status=Activated · GET Order.OrderNumber → e.g. "00000121"
10
Railway → Browser: 200 response
{ reply, tool_calls: [{tool:"place_b2b_order"}], checkout_session: {status:"placed", order_id:"00000121"} }

☁️ Salesforce B2B Order Flow

9-step process inside place_b2b_order tool

1. Auth & Session

Buyer logs in via Salesforce SOAP (login()). Connected App OAuth token is fetched for B2B Commerce REST calls. Both credentials stored in server session.

2. Get / Create WebCart

GET /commerce/webstores/{id}/carts?status=Active — reuses an existing active cart or creates one if none found.

3. Add CartItems

POST /carts/{id}/cartItems — adds each item from self.cart with quantity. Existing items are updated in place.

4. Set PO Number

PATCH /carts/{id} with poNumber. Non-fatal — if the PATCH fails, order proceeds without PO reference.

5. Create Order SObject

POST /sobjects/Order with AccountId (from buyer's account), EffectiveDate, Status=Draft, BillingAddress from account.

6. Create OrderItems

POST /sobjects/OrderItem for each line — links to Order, Product2, Pricebook2Entry, quantity, unit price.

7. Activate Order

PATCH /sobjects/Order/{id} with Status=Activated. This triggers Salesforce order processing workflows.

8. Read OrderNumber

GET /sobjects/Order/{id}?fields=OrderNumber,Status,TotalAmount → returns the human-readable order number (e.g. 00000121).

9. Close Cart

Server clears self.cart. Optionally closes the WebCart. checkout_session.status = "placed" signals the React frontend to clear the cart sidebar.

⚠️ Known Architectural Constraints

In-Memory State Only

The agent instance, cart, quotes, and conversation history live in Railway process memory. A Railway redeploy or service restart wipes all state. Users must log in again after a deploy.

Single Agent Instance

One TrackedAgent object is shared across all HTTP requests. A single-user demo. For multi-user production: session isolation per user ID would be required.

Salesforce IP Allowlist

Railway's egress IPs must be added to Salesforce Trusted IP Ranges for the Connected App, or OAuth will be blocked. Railway IPs change with deploys.

Full History Each Turn

Gemini receives the full contents[] on every turn (no server-side pruning). Long sessions increase token usage and latency linearly.
