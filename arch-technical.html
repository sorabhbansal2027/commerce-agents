2
Session created → session_id stored
Subsequent requests carry X-Session-Id header. Error displayed inline on failure.
3
User types message → Enter / Send
_submit(text) → pushes USER bubble, calls _startTurn(text), renders SKELETON placeholder
4
POST {apiUrl}{apiPrefix}/chat with SSE response
Body: {"message": text}. Headers: Accept: text/event-stream, application/json. AbortController disabled inside LWS.
5
Stream decoded line-by-line via ReadableStream
Events: text_delta, progress, ui, ui_partial, change_update, suggestions, turn_complete, error
6
UI events render generative components
kv_list/stat_group → KV card; ranked_list/product_list → ranked rows card; change_update → approve/discard widget
7
Change approve/discard → POST changes/{id}/apply|discard
Merchant writes gate: backend applies only after host confirmation. Status updates inline.

UCP — Universal Commerce Protocol

Cross-agent discovery via /.well-known/ucp manifest. Any UCP-compatible AI (Gemini, etc.) auto-discovers capabilities and shops through standard REST primitives. Live on Railway.

Live URL: https://diligent-flow-production-afd7.up.railway.app — UCP manifest at /.well-known/ucp
Endpoints (ucp.py)
GET/.well-known/ucp
Capability manifest. Cached max-age=300. Describes product_discovery, cart_management, checkout, payment_handlers, REST + MCP transport hints.
→ {schema_version, business, capabilities, payment_handlers, transport, agent_hints}
GET/ucp/products?q=&category=&min_price=&max_price=&in_stock=&limit=
Sessionless product search. Max limit=50. Supports full_text_search, category_filter, price_range_filter, availability_filter.
→ {products: [{product_id, title, price, currency, in_stock, brand?, image_url?, rating?, category?}], total, query}
GET/ucp/products/{product_id}
Product detail. product_id may contain slashes. Returns 404 with {error: "product_not_found"} if not found.
→ same UCP product schema as search row
POST/ucp/checkout-sessions 201
Create a pending checkout session from line items. No charge made. Buyer must confirm through storefront or agent.
body: {line_items: [{product_id, quantity}], buyer: {name, email}, payment_handler}
→ {checkout_session_id, status:"pending", line_items, subtotal, currency, payment_handler, buyer, agent_note}
GET/ucp/checkout-sessions/{session_id}
Session status lookup. Reference implementation does not persist sessions — integrate with OMS for live status.
→ {checkout_session_id, status:"pending", note}

Six Skills

commerce-architecture

Explains the channel topology, role separation, backend contract, and extension points. Used when reasoning about adding a new vertical or modifying routing.

commerce-evals

Eval harness conventions: writing test cases against tool calls, grading criteria, and running the pytest eval suites in tests/.

commerce-merchant-operations

Merchant agent patterns: change staging, host-approval gate, analysis delegate, merchant-side skill descriptions.

commerce-prompt-caching

How the static prompt + tools bytes are kept identical per turn to hit Anthropic prompt cache. Cache-control header placement.

commerce-trust-safety

Third-party content fencing rules, provenance gating on writes, the checkout no-charge invariant, and the loopback guard in host.py.

commerce-ui-tools

Presentation tool schema design: PresentationExtension, component routing in generative.tsx, the validation → fill → render pipeline.

Design Rules Enforced by Plugin Skills
CLAUDE.md — core invariants
# One model owns the conversation
# A rule goes in a tool description, the prompt, or a skill by how often it applies

# Static prompt and tools[] are the same bytes on every turn (cache hit)
# Per-request data goes in the fenced block after the breakpoint

# UI is presentation tool calls; validated and filled on server; streamed as "ui" events
# Third-party content is fenced data; writes are provenance-gated and capped in code
# checkout charges nothing; merchant writes apply only through host approval

# Core is domain-neutral; a vertical adds UI through PresentationExtension
# Each mechanism is defined once, in commerce_common or a role core

# A change to prompt text, tool description, skill, or fence notice
# re-derives system.md; scripts/check.py compares them
