Migration Steps — Railway → AWS

  • 1
    Create ECR repository Repo has CI
    aws ecr create-repository --repository-name commerce-agent-gemini --region us-east-1 — one-time setup. The GitHub Actions workflow handles all future pushes.
  • 2
    Create ECS cluster + Fargate service Template in repo
    Use salesforce/infrastructure/aws/ecs-task-definition.json — fill in <ACCOUNT_ID>, <REGION>, add GEMINI_API_KEY to the secrets block. Register with aws ecs register-task-definition.
  • 3
    Store secrets in AWS Secrets Manager Client action
    Create one secret: commerce-agents/gemini with keys GEMINI_API_KEY, SF_CLIENT_ID, SF_CLIENT_SECRET, SF_INSTANCE_URL, SF_COMMUNITY_URL. Update the task definition ARN references.
  • 4
    Set GitHub Actions variables + secrets Workflow in repo
    GitHub → Settings → Variables: ECR_REGISTRY, AWS_REGION, ECS_CLUSTER, SANDBOX_ECS_SERVICE, SANDBOX_TASK_DEF_FAMILY. GitHub → Secrets: AWS_ROLE_ARN. The _deploy-backend-aws.yml workflow then runs on every push to main.
  • 5
    Set up ALB + HTTPS listener Client action
    Create an Application Load Balancer, target group pointing at ECS service (port 8090), and HTTPS listener (ACM certificate). Note the ALB DNS name — this becomes your new app URL.
  • 6
    Update Salesforce Connected App callback URL Client action
    In Salesforce Setup → Connected Apps, change the OAuth Callback URL from https://perfect-achievement-production-83ee.up.railway.app/api/oauth/callback to https://your-alb-domain.example.com/api/oauth/callback. Also update SF_CALLBACK_URL env var in Secrets Manager.
  • 7
    Update Salesforce Trusted IP Ranges Client action
    ECS Fargate tasks egress through a NAT Gateway — add its static Elastic IP to Salesforce → Setup → Trusted IP Ranges for the Connected App. Without this, OAuth token exchange is blocked.
  • 8
    Push to main — CI deploys automatically Fully automated
    GitHub Actions builds the Docker image from Dockerfile.gemini, pushes to ECR, updates the ECS task definition, deploys to Fargate, runs the health check (GET /api/health), and auto-rolls back on failure. Zero manual steps after setup.
⚠️

Gemini-specific gap: The existing AWS workflow and ECS task definition were written for the Claude/Salesforce backend (port 8000, ANTHROPIC_API_KEY). To use them for the Gemini assistant you need to (a) add GEMINI_API_KEY to the task definition secrets block, (b) change the container port from 8000 → 8090 (or override with PORT env var), and (c) update the GitHub repo variables to point at a Gemini-specific ECS service. These are configuration changes — no code changes to the Python or React app.

✅

Bottom line: The repo gives you the Dockerfile, the CI/CD GitHub Actions workflow, the ECS task definition template, and the IAM policy. What you must supply: an AWS account with ECR + ECS + ALB created, your Salesforce org credentials in Secrets Manager, your Gemini API key in Secrets Manager, and five GitHub repo variables. Estimated one-time setup time: 2–3 hours.
