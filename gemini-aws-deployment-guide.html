⚠️

Gemini vs. the existing template. The repo's ECS task definition and CI workflow were written for the Claude/Salesforce backend (port 8000, ANTHROPIC_API_KEY). This guide adapts them for the Gemini assistant (port 8090, GEMINI_API_KEY). Application code is unchanged — only infrastructure config differs.

🔧

Prerequisites. AWS CLI v2 installed and configured with admin credentials (aws configure). Docker installed locally. GitHub repo access. Roughly 2–3 hours for first-time setup.

Phase 1 of 4

🟠 AWS One-Time Setup

Run these once. After this, every deploy is fully automated via GitHub Actions.
1

Create the IAM Role for GitHub Actions (OIDC)

No long-lived AWS access keys. GitHub Actions authenticates via OIDC — a short-lived token is issued per workflow run. The trust policy is already in the repo at salesforce/infrastructure/aws/iam-oidc-policy.json.

📋

First, enable the GitHub OIDC provider in your AWS account if not already done:

Shellone-time, per AWS account
# Enable GitHub OIDC provider (one-time per AWS account)
aws iam create-open-id-connect-provider \
  --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com \
  --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1
Shellsalesforce/infrastructure/aws/iam-oidc-policy.json → adapted
# 1. Edit the trust policy — fill in your values
cat > /tmp/trust-policy.json <<'EOF'
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {
      "Federated": "arn:aws:iam::YOUR_ACCOUNT_ID:oidc-provider/token.actions.githubusercontent.com"
    },
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": { "token.actions.githubusercontent.com:aud": "sts.amazonaws.com" },
      "StringLike":  { "token.actions.githubusercontent.com:sub": "repo:YOUR_ORG/YOUR_REPO:*" }
    }
  }]
}
EOF

# 2. Create the role
aws iam create-role \
  --role-name GitHubActionsCommerceAgents \
  --assume-role-policy-document file:///tmp/trust-policy.json

# 3. Attach required permissions
aws iam attach-role-policy \
  --role-name GitHubActionsCommerceAgents \
  --policy-arn arn:aws:iam::aws:policy/AmazonECS_FullAccess

aws iam attach-role-policy \
  --role-name GitHubActionsCommerceAgents \
  --policy-arn arn:aws:iam::aws:policy/AmazonEC2ContainerRegistryPowerUser

# Save the role ARN — you'll need it for GitHub secrets
aws iam get-role --role-name GitHubActionsCommerceAgents \
  --query 'Role.Arn' --output text
# → arn:aws:iam::123456789012:role/GitHubActionsCommerceAgents

Store Secrets in AWS Secrets Manager

All sensitive values go into Secrets Manager. The ECS task definition references them by ARN — the container gets them as environment variables at runtime, never in the image or Git.

⚑

Gemini change: The repo template stores ANTHROPIC_API_KEY. For the Gemini assistant, store GEMINI_API_KEY instead.

Shellstore all secrets (run once, update as needed)
# Gemini API key (Google AI Studio)
aws secretsmanager create-secret \
  --name commerce-agents/gemini \
  --secret-string '{"GEMINI_API_KEY":"AIza...your-key..."}'

# Salesforce credentials (your org's Connected App)
aws secretsmanager create-secret \
  --name commerce-agents/salesforce \
  --secret-string '{
    "SF_CLIENT_ID":      "3MVG...your-consumer-key...",
    "SF_CLIENT_SECRET":  "your-consumer-secret",
    "SF_INSTANCE_URL":   "https://atci-b2b-lex--b2bpoc.sandbox.my.salesforce.com",
    "SF_COMMUNITY_URL":  "https://your-community-url.force.com/your-site",
    "SF_CALLBACK_URL":   "https://YOUR_ALB_DOMAIN/api/oauth/callback"
  }'

# Get the ARNs — paste these into the task definition
aws secretsmanager describe-secret \
  --secret-id commerce-agents/gemini \
  --query 'ARN' --output text

aws secretsmanager describe-secret \
  --secret-id commerce-agents/salesforce \
  --query 'ARN' --output text

7

Create the ALB + ECS Service

The Application Load Balancer provides HTTPS and a stable DNS name. The ECS service keeps the Fargate task running and registers it with the ALB target group.

ShellALB setup (use your VPC/subnet IDs)
# 1. Create a security group for the ALB (allows inbound 443/80)
ALB_SG=$(aws ec2 create-security-group \
  --group-name gemini-alb-sg \
  --description "Gemini Commerce ALB" \
  --vpc-id YOUR_VPC_ID \
  --query 'GroupId' --output text)

aws ec2 authorize-security-group-ingress \
  --group-id $ALB_SG --protocol tcp --port 443 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress \
  --group-id $ALB_SG --protocol tcp --port 80  --cidr 0.0.0.0/0

# 2. Create the ALB
ALB_ARN=$(aws elbv2 create-load-balancer \
  --name gemini-commerce-alb \
  --subnets YOUR_PUBLIC_SUBNET_1 YOUR_PUBLIC_SUBNET_2 \
  --security-groups $ALB_SG \
  --scheme internet-facing \
  --type application \
  --query 'LoadBalancers[0].LoadBalancerArn' --output text)

# 3. Create target group pointing at port 8090
TG_ARN=$(aws elbv2 create-target-group \
  --name gemini-commerce-tg \
  --protocol HTTP \
  --port 8090 \
  --vpc-id YOUR_VPC_ID \
  --target-type ip \
  --health-check-path /api/health \
  --health-check-interval-seconds 30 \
  --healthy-threshold-count 2 \
  --query 'TargetGroups[0].TargetGroupArn' --output text)

# 4. HTTPS listener (requires ACM certificate)
CERT_ARN="arn:aws:acm:us-east-1:YOUR_ACCOUNT_ID:certificate/YOUR_CERT_ID"
aws elbv2 create-listener \
  --load-balancer-arn $ALB_ARN \
  --protocol HTTPS --port 443 \
  --certificates CertificateArn=$CERT_ARN \
  --default-actions Type=forward,TargetGroupArn=$TG_ARN

# Get the ALB DNS — this is your app URL
aws elbv2 describe-load-balancers \
  --load-balancer-arns $ALB_ARN \
  --query 'LoadBalancers[0].DNSName' --output text
# → gemini-commerce-alb-123456789.us-east-1.elb.amazonaws.com
ShellECS service (references the task definition registered in step 6)
# Security group for ECS tasks (allows ALB inbound on 8090)
TASK_SG=$(aws ec2 create-security-group \
  --group-name gemini-tasks-sg \
  --description "Gemini Commerce ECS tasks" \
  --vpc-id YOUR_VPC_ID \
  --query 'GroupId' --output text)

aws ec2 authorize-security-group-ingress \
  --group-id $TASK_SG \
  --protocol tcp --port 8090 \
  --source-group $ALB_SG

# Outbound: allow tasks to reach Gemini API, Salesforce (port 443)
aws ec2 authorize-security-group-egress \
  --group-id $TASK_SG \
  --protocol tcp --port 443 --cidr 0.0.0.0/0

# Create the ECS service
aws ecs create-service \
  --cluster commerce-agents \
  --service-name gemini-commerce \
  --task-definition gemini-commerce \
  --desired-count 1 \
  --launch-type FARGATE \
  --network-configuration "awsvpcConfiguration={
    subnets=[YOUR_PRIVATE_SUBNET_1,YOUR_PRIVATE_SUBNET_2],
    securityGroups=[$TASK_SG],
    assignPublicIp=DISABLED
  }" \
  --load-balancers "targetGroupArn=$TG_ARN,containerName=gemini-commerce,containerPort=8090"
💡

NAT Gateway required. Tasks in private subnets need a NAT Gateway to reach Gemini API and Salesforce outbound. Attach it to the private route table. Note the NAT Gateway's Elastic IP — you'll add it to Salesforce Trusted IP Ranges in step 11.

Add a Caller Workflow and Trigger the First Deploy

The repo's _deploy-backend-aws.yml is a reusable workflow — it must be called from a trigger workflow. Create one:

YAML.github/workflows/deploy-gemini-aws.yml (create this file)
name: Deploy Gemini → AWS

on:
  push:
    branches: [main]
    paths:
      - 'scripts/gemini_web_server.py'
      - 'examples/gemini-storefront/**'
      - 'examples/demo_common/gemini_ucp_agent.py'
      - 'Dockerfile.gemini'
  workflow_dispatch:    # manual trigger from GitHub UI

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
    outputs:
      image-tag: ${{ steps.meta.outputs.version }}

    steps:
      - uses: actions/checkout@v4

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region:     ${{ vars.AWS_REGION || 'us-east-1' }}

      - name: Login to ECR
        uses: aws-actions/amazon-ecr-login@v2

      - name: Build and push Gemini image
        id: meta
        run: |
          TAG=${{ github.sha }}
          IMAGE=${{ vars.ECR_REGISTRY }}/gemini-commerce:$TAG
          docker build -f Dockerfile.gemini -t $IMAGE .
          docker push $IMAGE
          echo "version=$TAG" >> $GITHUB_OUTPUT

  deploy:
    needs: build-and-push
    uses: ./.github/workflows/_deploy-backend-aws.yml
    with:
      environment: sandbox
      image-tag:   ${{ needs.build-and-push.outputs.image-tag }}
    secrets: inherit
Shellpush the workflow to trigger the first deploy
git add .github/workflows/deploy-gemini-aws.yml
git commit -m "ci: add Gemini AWS deploy workflow"
git push origin main

# Watch it in GitHub → Actions tab
# Build: ~5 min (Vite build + Docker push)
# Deploy: ~3 min (ECS rolling update)
🔄

After the first deploy, every git push to main that touches Gemini files automatically redeploys. The workflow: builds the Docker image → pushes to ECR → updates the ECS task definition → deploys → health checks → rolls back on failure. You never touch the AWS console again for routine deploys.

Update Connected App Callback URL

The Salesforce Connected App's OAuth Callback URL must match exactly what your app sends. Change it from the Railway URL to your ALB URL.

Before (Railway)

https://perfect-achievement-production-
83ee.up.railway.app/api/oauth/callback

After (AWS ALB)

https://YOUR-ALB-DNS.us-east-1.elb.

Or your custom domain if you've set up Route 53.

Where to change it: Salesforce Setup → App Manager → find your Connected App → Edit → OAuth Settings → Callback URL.

Also update SF_CALLBACK_URL in AWS Secrets Manager (commerce-agents/salesforce) to match.

11

Update Salesforce Trusted IP Ranges

ECS Fargate tasks egress through a NAT Gateway with a fixed Elastic IP. Salesforce blocks OAuth token requests from unknown IPs — add it to the allowlist.

Shellfind your NAT Gateway Elastic IP
# Find the NAT Gateway attached to your private subnets
aws ec2 describe-nat-gateways \
  --query 'NatGateways[?State==`available`].[NatGatewayId,NatGatewayAddresses[0].PublicIp]' \
  --output table
# → e.g. 54.123.45.67

Where to add it in Salesforce: Setup → Network Access → New → enter the NAT Gateway IP as both Start IP and End IP → Save.

Or add it at the Connected App level: Setup → App Manager → your Connected App → Edit → IP Relaxation → set to "Relax IP restrictions" (less secure) or use the org-wide Trusted IP Range.
